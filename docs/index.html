The Problem

Centralized AI oracles are black boxes

Today's AI oracles run behind closed APIs. No one can verify how the model reached its conclusion. The operator can manipulate inputs, cherry-pick outputs, or silently swap models. Prediction markets built on these oracles inherit all of that opacity.

Opaque Inference

No cryptographic proof that the AI model actually ran inside a trusted environment. The operator could fabricate any response.

Mutable Evidence

Resolution receipts live on centralized servers. They can be edited, deleted, or retroactively altered without detection.

No Accountability

Without on-chain recording and verified identity, there is no audit trail. Disputes become he-said-she-said.

Architecture

Five-step atomic pipeline

Each oracle resolution flows through a deterministic pipeline. If any step fails, nothing is recorded. The receipt binds real data, AI reasoning, TEE attestation, and on-chain proof into a single verifiable artifact.

01

Real-Time Market Data

Fetches live data from public sources — ETH gas prices from mainnet RPCs (eth.llamarpc.com), BTC/ETH/SOL prices from CoinGecko. No synthetic data. The raw JSON is hashed with keccak256 for integrity binding.

02

TEE-Attested Inference

Discovers TEE providers on-chain via 0G Compute SDK. Calls inference directly on the provider — not through the Router. The provider's TEE environment signs the response with its private key.

03

Per-Inference Signature Verification

Fetches the provider's ECDSA signature for this specific chat. Recovers the signer via ecrecover and verifies it against the on-chain TEE signer address from the InferenceServing contract.

04

Immutable Receipt Upload

The full receipt — AI response, real data, TEE signature, integrity hashes — is uploaded to 0G Storage as a Merkle tree. Returns a permanent root hash. The data cannot be altered after upload.

05

On-Chain Recording

Calls recordResolution() on the ERC-7857 PrecisionOracleID contract. The storage root, TEE signature, and signer address are verified on-chain. The resolution is permanently linked to the agent's NFT identity.

0G Integration Depth

Four layers of the 0G stack

Not surface-level usage. Each integration is structural — the oracle cannot function without it.

0G Compute

Direct provider inference, not just Router

On-chain provider discovery via InferenceServing contract. Direct TEE-attested inference calls to provider broker URLs. Per-inference ECDSA signature fetched and verified against on-chain signer.

0G Storage

Merkle tree receipts, permanent and verifiable

Full resolution receipts uploaded as Merkle trees via the 0G TS SDK and Indexer. Returns a root hash that serves as the tamper-evident anchor. Anyone can download and verify the receipt.

0G Chain

ERC-7857 smart contracts, TEE signer registry

PrecisionOracleID implements the real ERC-7857 standard by 0G Labs. On-chain TEE signer registry with ECDSA proof verification. Atomic recordResolution() links storage roots to agent identity.

OpenClaw

SKILL.md skill manifest for agent orchestration

Full SKILL.md manifest enabling any OpenClaw-compatible agent to invoke the oracle as a composable skill. Defines inputs, outputs, and invocation protocol for agentic workflows.

Quick Start

Deploy and run in four steps

1Install

git clone https://github.com/YOUR_USERNAME/sealed-precision-oracle
cd oracle
nvm use  # Node 20.17.0
npm install --legacy-peer-deps

2Configure

cp .env.example .env
# Add your private key
# Get testnet tokens:
# cloud.google.com/application/web3/faucet/0g/galileo

3Deploy

npm run compile
npm run deploy
# Deploys OracleDataVerifier + PrecisionOracleID
# Copy ORACLE_CONTRACT_ADDRESS to .env

4Run

npm run oracle
# or with a custom question:
npx ts-node src/oracle.ts \
  "Will ETH gas exceed 30 gwei?"
